# PRD: Сайт для ведения семейного бюджета

## 1. Описание проекта

Одностраничный сайт для учёта доходов и расходов семьи, просмотра месячного баланса и отслеживания цели накопления. Сайт работает локально в браузере и сохраняет данные на устройстве пользователя.

## 2. Цель

Помочь семье видеть, сколько денег поступило и было потрачено за выбранный месяц, какой остаток доступен и насколько близко достижение финансовой цели.

## 3. Целевая аудитория

Люди и семьи, которым нужен простой инструмент для повседневного учёта бюджета без регистрации и подключения к банковским счетам.

## 4. Платформа и ограничения

- Один файл `index.html` с HTML, CSS и JavaScript.
- Работа в современном браузере без сервера.
- Без сторонних библиотек.
- Сохранение данных в `localStorage` текущего браузера и устройства.
- Интерфейс на русском языке.
- Денежная валюта — тенге (₸).

## 5. Основные пользовательские сценарии

1. Пользователь добавляет доход или расход.
2. Выбирает месяц и просматривает операции за этот период.
3. Проверяет общие доходы, расходы и остаток за месяц.
4. Создаёт цель накопления и указывает текущую сумму.
5. Возвращается на сайт позднее и видит сохранённые данные.
6. При необходимости удаляет отдельную запись или очищает все данные после подтверждения.

## 6. Функциональные требования

### 6.1. Доходы

Пользователь может добавить доход со следующими полями:

- Название.
- Сумма.
- Дата.

Для каждой записи доступно удаление.

### 6.2. Расходы

Пользователь может добавить расход со следующими полями:

- Название.
- Сумма.
- Категория.
- Дата.

Доступные категории:

- Продукты.
- Жильё и коммунальные услуги.
- Транспорт.
- Здоровье.
- Дети.
- Развлечения.
- Прочее.

Для каждой записи доступно удаление.

### 6.3. Сводка за месяц

Для выбранного месяца сайт показывает:

- Сумму доходов.
- Сумму расходов.
- Остаток: доходы минус расходы.

Сводка учитывает только операции выбранного месяца. Пользователь может выбрать другой месяц для просмотра его операций и итогов.

### 6.4. Цель накопления

Пользователь может задать и изменить:

- Название цели.
- Целевую сумму.
- Уже накопленную сумму.

Сайт показывает:

- Прогресс в процентах.
- Полосу прогресса.
- Остаток до достижения цели.

Значения цели сохраняются после перезагрузки страницы.

### 6.5. Хранение данных

- Доходы, расходы и цель сохраняются в `localStorage`.
- Данные остаются доступными после перезагрузки страницы в том же браузере.
- На сайте есть команда очистки всех данных.
- Перед очисткой сайт просит подтверждение.

### 6.6. Проверка ввода

Нельзя добавлять запись, если:

- Не указано название.
- Сумма отсутствует, равна нулю или отрицательна.
- Сумма введена в некорректном формате.

При ошибке сайт показывает понятное сообщение рядом с формой или в виде уведомления.

## 7. Требования к интерфейсу

- Аккуратный, понятный и визуально спокойный дизайн.
- Адаптивная вёрстка для компьютеров и телефонов.
- Основные разделы страницы:
  1. Выбор месяца и сводка.
  2. Форма добавления дохода.
  3. Форма добавления расхода.
  4. Список операций.
  5. Цель накопления.
- Кнопки и поля имеют понятные подписи.
- Денежные суммы отображаются в тенге.
- Пустые списки сопровождаются коротким пояснением.

## 8. Нефункциональные требования

- Код находится в одном HTML-файле.
- Основные части JavaScript снабжены короткими комментариями.
- Страница должна корректно работать при вводе данных с клавиатуры и сенсорного экрана.
- Перед удалением всех данных требуется явное подтверждение.

## 9. За пределами первой версии

В первую версию не входят:

- Регистрация и учётные записи.
- Синхронизация между устройствами.
- Подключение к банкам и импорт транзакций.
- Серверное хранение данных.
- Несколько отдельных профилей или бюджетов.

## 10. Критерии готовности

- Пользователь может добавить и удалить доход.
- Пользователь может добавить и удалить расход с категорией.
- Суммы и остаток пересчитываются после изменения операций.
- Переключение месяца показывает операции и итоги выбранного месяца.
- Цель накопления отображается с процентом и прогресс-баром.
- Данные сохраняются после перезагрузки страницы.
- Некорректный ввод сопровождается понятным сообщением.
- Очистка данных требует подтверждения.
- Страница остаётся удобной на телефоне и компьютере.
